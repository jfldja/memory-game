## 1. 背景與目的 ★

本專案開發一個公開的網頁翻牌記憶遊戲，同時作為一次貼近業界做法的完整開發流程演練：需求 → 設計 → 實作 → 測試 → 使用者驗收 → 發布。各階段由 agent 執行；產品負責人負責階段簽核、發布前的使用者驗收（UAT）與發布。

本輪成功的樣子：

1. 任何人透過公開網址，可在手機或電腦瀏覽器上遊玩三個關卡。
2. 所有 Must 需求通過自動化測試與使用者驗收後，由產品負責人發布 v1.0.0。

## 2. 現況基準

無既有系統，從零開始。本節不適用。

## 4. 範圍 ★

### 4.1 本輪範圍內

- 三個關卡的翻牌遊戲，每關 12 張牌。
- 計時、步數、每關時間上限、每關三次提示、暫停。
- 勝利畫面與失敗畫面。
- 存於玩家瀏覽器的個人成績紀錄，以及清除紀錄功能。
- 原創牌面圖像（由 Claude 繪製）。
- 公開 GitHub 版本庫、自動化測試、CI、GitHub Pages 發布。

## 5. 術語表

| 術語 | 定義 |
|---|---|
| 牌 | 牌面區中的一個可點擊單位，有「背面朝上」「正面朝上」「已配對」三種狀態 |
| 牌面 | 牌正面的圖像。每關有 6 種牌面，每種 2 張 |
| 一對 | 牌面相同的兩張牌 |
| 配對 | 玩家連續翻開的兩張牌為同一對 |
| 一次遊玩 | 從進入某一關開始，到勝利、失敗、重新開始或離開該關為止 |
| 步數 | 一次遊玩中，玩家翻開「第二張牌」的次數（每次配對嘗試算 1 步） |
| 已用時間 | 一次遊玩中，自第一張牌翻開起累計的時間，不含暫停期間，至勝利或失敗時停止 |
| 顯示值 | 已用時間無條件捨去到 0.1 秒的數值，例如 89.96 秒的顯示值為 89.9。畫面顯示、時間上限判定、結果畫面、紀錄的比較與保存，一律使用顯示值 |
| 時間上限 | 每關允許的最大已用時間 |
| 提示 | 玩家主動使用、標示一對尚未配對的牌位置的功能；使用提示不會翻開任何牌 |
| 提示標示 | 使用提示後一對牌被標示的 2 秒（±0.1 秒）期間；暫停時剩餘時間一併暫停 |
| 翻錯鎖定 | 兩張翻開的牌不是一對時，自第二張牌翻開起算、牌維持正面的 1 秒（±0.1 秒）期間；暫停時剩餘時間一併暫停 |
| 無法使用 | 按鈕仍可見、呈現停用樣式，點擊後沒有任何效果 |
| 隨機排列 | 每次遊玩開始時，每種牌面出現在每個位置的機率相同（各 1/6），且與前一次遊玩的排列無關 |
| 正面未配對的牌 | 正面朝上、但尚未成為已配對的牌：已翻開的第一張，或翻錯鎖定中的兩張 |
| 紀錄 | 每關的「最佳時間」與「最少步數」兩項，各自附帶取得該紀錄那次遊玩所用的提示次數 |
| 優於 | 時間：顯示值較小；步數：數值較小。相等不算優於 |
| 關卡／難度 | 同一個概念。文件中以「第 1、2、3 關」指稱；對玩家一律顯示為難度名稱：第 1 關＝簡單、第 2 關＝普通、第 3 關＝困難 |
| 選單 | 遊戲開啟後的第一個畫面，用來選擇難度、查看紀錄、清除紀錄 |
| 發布 | 產品負責人在 GitHub 建立版本標籤與 release notes，並讓公開網址提供該版本（見 11 節） |
| UAT | 使用者驗收測試：產品負責人依 10.3 節清單，在自己的手機與電腦上親自測試 |

## 6. 功能需求 ★

撰寫慣例：句式「應」= Must，「宜」= Should，「可」= Could。Must 未完成即不能發布；Should 優先於 Could，資源不足可延後；Could 有餘力再做。

### 6.1 遊戲進行（GP）

| 編號 | 優先 | 需求 |
|---|---|---|
| GP-1 | M | 每次遊玩開始時，牌面區應顯示 12 張背面朝上的牌，由 6 種牌面各 2 張組成 |
| GP-2 | M | 每次遊玩開始時（含重玩），12 張牌的位置應重新隨機排列 |
| GP-3 | M | 點擊一張背面朝上的牌時，該牌應翻為正面朝上 |
| GP-4 | M | 翻開的兩張牌為同一對時，兩張牌應維持正面朝上並成為已配對 |
| GP-5 | M | 翻開的兩張牌不是同一對時，兩張牌應維持正面朝上 1 秒後翻回背面（容差 ±0.1 秒） |
| GP-6 | M | 翻錯鎖定期間，點擊任何牌應無效果 |
| GP-7 | M | 點擊正面朝上或已配對的牌應無效果，且步數不變 |
| GP-8 | M | 6 對全部配對時，系統應結束該次遊玩並顯示勝利畫面 |

### 6.2 計時與步數（TM）

| 編號 | 優先 | 需求 |
|---|---|---|
| TM-1 | M | 已用時間應從該次遊玩第一張牌翻開時開始累計 |
| TM-2 | M | 遊戲中應顯示已用時間的顯示值（無條件捨去到 0.1 秒） |
| TM-3 | M | 每翻開一次第二張牌，步數應加 1 |
| TM-4 | M | 遊戲中應顯示目前步數 |
| TM-5 | M | 勝利或失敗時，已用時間應停止累計 |

### 6.3 關卡（LV）

牌面相似度以三個屬性定義：**形狀**、**顏色**、**細節**（形狀內部的圖紋，例如點數、線條方向）。

| 編號 | 優先 | 需求 |
|---|---|---|
| LV-1 | M | 系統應提供第 1、2、3 關，共 3 個關卡 |
| LV-2 | M | 第 1 關的 6 種牌面，任兩種之間的形狀應不同，且顏色應不同 |
| LV-3 | M | 第 2 關的 6 種牌面應為同一顏色，任兩種之間的形狀應不同 |
| LV-4 | M | 第 3 關的 6 種牌面應為同一形狀與同一顏色，任兩種之間只有細節不同 |
| LV-5 | M | 時間上限應為：第 1 關 90 秒、第 2 關 75 秒、第 3 關 60 秒 |
| LV-6 | M | 已用時間的顯示值達到時間上限、而 6 對尚未全部配對時，系統應結束該次遊玩並顯示失敗畫面 |
| LV-7 | M | 選單中三個關卡應隨時都能直接選擇，不需先通過其他關卡 |
| LV-8 | M | 遊戲中應顯示目前難度名稱與該關的時間上限 |
| LV-9 | M | 選單、遊戲中與結果畫面應以難度名稱（簡單、普通、困難）標示關卡，不顯示「第 N 關」 |

### 6.4 提示（HT）

| 編號 | 優先 | 需求 |
|---|---|---|
| HT-1 | M | 每次遊玩開始時，剩餘提示次數應為 3 |
| HT-2 | M | 使用提示時，系統應標示一對尚未配對的牌，標示持續 2 秒（±0.1 秒） |
| HT-3 | M | 每使用一次提示，剩餘提示次數應減 1 |
| HT-4 | M | 剩餘提示次數為 0 時，提示按鈕應無法使用 |
| HT-5 | M | 遊戲中應顯示剩餘提示次數 |
| HT-6 | — | 已刪除（併入 HT-7、PS-10） |
| HT-7 | M | 有正面未配對的牌時（包含已翻開一張、翻錯鎖定期間），提示按鈕應無法使用 |
| HT-8 | M | 提示標示期間，提示按鈕應無法使用 |
| HT-9 | M | 使用提示不應改變任何牌的正反面，也不應改變步數 |
| HT-10 | M | 該次遊玩第一張牌翻開前，提示按鈕應無法使用 |

### 6.5 暫停（PS）

| 編號 | 優先 | 需求 |
|---|---|---|
| PS-1 | M | 遊戲中點擊暫停鍵時，已用時間應停止累計 |
| PS-2 | M | 暫停中，點擊任何牌應無效果 |
| PS-3 | M | 暫停後點擊繼續時，已用時間應從暫停時的數值繼續累計 |
| PS-4 | M | 暫停中，牌面區應被遮蔽，看不到任何牌面 |
| PS-5 | S | 頁面切換到背景（切換分頁、切換 App）時，遊戲宜自動暫停 |
| PS-6 | — | 已拆分為 PS-7、PS-8 |
| PS-7 | M | 遊戲中（含暫停中）應能回到選單；該次遊玩結束且不更新紀錄 |
| PS-8 | S | 遊戲中宜能重新開始本關 |
| PS-9 | M | 暫停時，翻錯鎖定與提示標示的剩餘時間應一併暫停，繼續後從剩餘時間接續 |
| PS-10 | M | 暫停中，提示按鈕應可見且無法使用（不得被暫停畫面或遮蔽層蓋住） |

### 6.6 結果畫面（RS）

| 編號 | 優先 | 需求 |
|---|---|---|
| RS-1 | M | 勝利畫面應顯示本次的已用時間、步數與使用提示次數 |
| RS-2 | M | 勝利畫面與失敗畫面應提供「重玩本關」 |
| RS-3 | M | 勝利畫面與失敗畫面應提供「回到選單」 |
| RS-4 | S | 本次結果優於該項既有紀錄、或該項尚無紀錄時，勝利畫面宜在對應項目旁標示「新紀錄」 |
| RS-5 | S | 簡單與普通的勝利畫面宜提供「挑戰下一個難度」 |

### 6.7 成績紀錄（RC）

| 編號 | 優先 | 需求 |
|---|---|---|
| RC-1 | M | 系統應為每關分別保存「最佳時間」與「最少步數」兩項紀錄，兩項可以來自不同次遊玩 |
| RC-2 | M | 只有勝利的遊玩才應更新紀錄；失敗或中途離開的遊玩不更新 |
| RC-3 | M | 本次結果優於既有紀錄、或該項尚無紀錄時，系統應以本次結果取代；相等時不取代（時間以顯示值比較與保存） |
| RC-4 | M | 每項紀錄應保存取得該紀錄那次遊玩所用的提示次數，並顯示在紀錄旁 |
| RC-5 | M | 選單應顯示三關各自的兩項紀錄；尚無紀錄的項目顯示「—」 |
| RC-6 | M | 在同一瀏覽器關閉並重新開啟頁面後，紀錄應保留 |
| RC-7 | M | 選單應提供「清除紀錄」按鈕，經玩家確認後清除三關全部紀錄；玩家取消時紀錄不變 |
| RC-8 | M | 保存的紀錄資料無法讀取或格式不符時，系統應視為無紀錄，選單與遊戲仍可正常使用 |
| RC-9 | S | 瀏覽器不允許保存資料時，遊戲宜仍可遊玩，並在選單顯示「紀錄無法保存」的提示 |

### 6.9 狀態與操作對照

本節彙整 3.8 狀態交互檢查的結果，供設計與測試使用。表中每一格都由上方需求或 8.2 假設規定；本節本身不新增需求。

**狀態 × 操作**

| 狀態 | 點背面朝上的牌 | 點正面朝上或已配對的牌 | 提示 | 暫停 | 回到選單 |
|---|---|---|---|---|---|
| 尚未開始計時 | 翻開，開始計時（GP-3、TM-1） | 不適用 | 不可用（HT-10） | 可用 | 可用（PS-7） |
| 計時中、無正面未配對的牌 | 翻開（GP-3） | 無效果（GP-7） | 剩餘次數大於 0 時可用 | 可用 | 可用 |
| 已翻開一張 | 翻開為第二張，步數加 1（TM-3） | 無效果（GP-7） | 不可用（HT-7） | 可用 | 可用 |
| 翻錯鎖定 | 無效果（GP-6） | 無效果（GP-6） | 不可用（HT-7） | 可用，鎖定倒數暫停（PS-9） | 可用 |
| 提示標示中 | 依並存的狀態 | 依並存的狀態 | 不可用（HT-8） | 可用，標示倒數暫停（PS-9） | 可用 |
| 暫停中 | 無效果（PS-2） | 無效果（PS-2） | 可見但不可用（PS-10） | 改為繼續（PS-3） | 可用（PS-7） |
| 勝利、失敗 | 不適用 | 不適用 | 不適用 | 不適用 | 結果畫面提供（RS-3） |

依 HT-7 與 HT-10，提示第一次能使用的時點，是第一次配對嘗試結束、且沒有正面未配對的牌之後。

「提示標示中」可與「計時中、無正面未配對的牌」「已翻開一張」「翻錯鎖定」並存，並存時兩者的規則都適用。

**狀態 × 計時器**

| 情況 | 已用時間 | 翻錯鎖定倒數 | 提示標示倒數 |
|---|---|---|---|
| 暫停中 | 停止（PS-1） | 暫停（PS-9） | 暫停（PS-9） |
| 時間上限在翻錯鎖定或提示標示中到達 | 停止，判定失敗（LV-6、A-5） | 取消 | 取消 |
| 勝利 | 停止（TM-5） | 不適用 | 取消 |
| 回到選單、重新整理、關閉頁面 | 該次遊玩結束（PS-7、A-6） | 取消 | 取消 |

### 8.3 設計候選方案（非需求，供設計階段參考）

- 牌面以內嵌 SVG 繪製；第 3 關的細節差異可用點數或線條方向。
- 版面：手機直向 3 欄 × 4 列，寬螢幕 4 欄 × 3 列。
- 審查紀錄可用 Pull Request 評論加固定標記（例如 `REVIEW: APPROVED <commit>`）；CI 以 GitHub API 讀取並比對最新 commit。
- 版本號格式可為 `1.0.0+<commit 短碼>`。
- UAT 期間凍結主分支（不合併任何 Pull Request），以免觸發 EQ-14 的重新驗收。
- 紀錄存於 localStorage，資料附版本欄位以便日後遷移。
- 已用時間以 `performance.now()` 計算，避免計時器累加誤差。
- 單元測試用 Node.js 內建測試執行器；端對端測試用 Playwright；CI 用 GitHub Actions。
- 遊戲邏輯（狀態機）與畫面分離，讓邏輯能在無瀏覽器環境下做單元測試。

## 10. 驗收標準 ★

### 10.1 驗證方式標示

每條驗收標準標示「自動」「人工」或「自動＋人工」。含「自動」者須依 EQ-4 有對應的自動化測試；「人工」由產品負責人執行或檢查，產品行為相關者納入 10.3 UAT 清單。時間相關的自動化測試以測試工具控制時鐘，檢查點落在需求容差的邊界上。例外：NFR-6 量測的是計時本身的準確度，必須使用真實時間，不得控制時鐘（控制時鐘時誤差恆為 0，測不出問題）。

### 10.2 功能驗收

**AC-GP-1**（自動）
- Given 選單畫面
- When 進入任一關
- Then 牌面區有 12 張牌，全部背面朝上
- Then 12 張牌由 6 種牌面組成，每種恰好 2 張；沒有任何牌面出現 1 次或 3 次以上

**AC-GP-2**（自動）
- 排列數：12 張牌、6 種牌面各 2 張，可區分的排列共 12!／(2!)⁶ ＝ 7,484,400 種。
- Given 同一關
- When 連續開始 20 次遊玩，記錄每次 12 個位置的牌面
- Then 每次排列都符合 AC-GP-1
- Then 任兩次相鄰的遊玩，排列都不相同（均勻隨機下，19 組相鄰中出現相同排列的機率約 19／7,484,400 ≈ 0.00025%，可視為不會誤判）
- Given 以開局排列結果統計 60,000 次開局（可在無瀏覽器環境執行）
- When 統計 12 個位置 × 6 種牌面共 72 格，每格的出現次數
- Then 每格都在 10,000 ± 500 之內
- 計算：每格期望值 60,000 × 1/6 ＝ 10,000，標準差 √(60,000 × 1/6 × 5/6) ≈ 91.3；±500 約為 ±5.5 個標準差，72 格中任一格誤判的機率約 72 × 4×10⁻⁸ ≈ 3×10⁻⁶。任一格偏離超過 5% 的排列方式（例如某牌面偏好固定位置）會被發現
- 反例：把排列改成固定順序後，兩個檢查都應失敗
